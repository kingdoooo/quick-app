# `deployer/.venv` 的依赖清单。**这个 venv 被四个包共用**：deployer 自己的测试，
# 以及 router 的 Edge 测试、panel 的测试、key-proxy 的测试（那三个没有自己的 venv，
# 借这个）。注意它与 `infra/.venv` 是两个：`aws_cdk` **只在** `infra/.venv` 里。
#
# **这份文件原本是手工维护的宽松钉**，2026-08-31 换机器时改成精确钉死。
# 原始的**直接依赖**声明保留在这里，因为精确清单看不出哪些是直接依赖：
#     pytest>=8 / moto[dynamodb,s3]>=5 / boto3 / sqlparse>=0.5 / -e ../contract
# 加 / 换依赖时改这一行的意图，再重新 freeze，别只往下面的 pin 里插一行。
#
# **只用于跑测试**，不进任何部署产物。
#
# 重建（**必须带 `--clear`**：shebang 是绝对路径，不带就一直报 bad interpreter；
# **必须在本目录下跑**——下面那条 `-e` 的相对路径是按**进程 cwd** 解析的，
# 不是按本文件的位置）：
#
#     cd site-builder/deployer
#     python3 -m venv --clear .venv
#     .venv/bin/pip install -r requirements-dev.txt
#
# 版本为**精确钉死**（含传递依赖），与 `mcp/requirements.txt` 同一个思路：
# 宁可过度钉死，也不要「新机器解析出另一套依赖集合」这种查不动的差异
# （CLAUDE.md 记着这条：不同版本解析出的依赖集合与 marker 分支不同）。
# **不写 git remote 形态的可编辑安装行**（`pip freeze` 会输出它）——那会把仓库地址
# 钉进来；本地相对路径不依赖任何远端。
